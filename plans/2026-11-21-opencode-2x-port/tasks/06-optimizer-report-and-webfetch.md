- [ ] Write matcher cases: “proposes an origin pattern when two distinct URLs have successful once approvals”, “proposes an owner pattern when both GitHub URLs belong to the same owner”, “withholds a pattern when GitHub approvals span owners”, “withholds a broader rule when the host has no supported tenant boundary”, and “withholds a pattern when one URL was approved only through Allow always”. Cover one repeated URL, host lookalikes, scheme and port changes, GitHub site-wide paths, tenant-boundary lookalikes and malformed or noncanonical names. Keep one report-level case that uses real SQLite and injects the inspector’s CLI result to prove evidence reaches the report. Run `bun test ./skills/opencode-permission-optimizer ./test`; expect red on the new URL matches and report shape.
- [ ] Group only `action === "webfetch"` resources with `successfulOnceApprovalsBySource[2] > 0`. Parse valid HTTP(S) URLs without credentials; reject URL spellings whose exact recorded text the proposed pattern cannot match, using the [pinned wildcard implementation](https://github.com/anomalyco/opencode/blob/v2.3.2/packages/core/src/util/wildcard.ts), not a parsed URL rewrite. Require two distinct URLs after fragment removal; the tool already strips fragments at request time. Reject wildcard metacharacters within the proposed literal scope. Ordinary hosts use the exact origin and `/*`.
- [ ] Use GitHub owner scopes only when the raw URL equals its canonical HTTPS `github.com` form and its path starts with two nonempty literal segments. The owner is a lowercase alphanumeric slug of 1–39 characters, with single hyphens permitted between alphanumerics. Reject a path with backslashes, percent-encoded separators or dot segments, and reserved site-wide first segments: `about`, `apps`, `collections`, `enterprise`, `events`, `explore`, `features`, `issues`, `login`, `marketplace`, `new`, `notifications`, `orgs`, `pricing`, `pulls`, `search`, `security`, `settings`, `signup`, `sponsors`, `topics`, `trending`. Require the workflow to establish that the first segment identifies the intended owner before recommending; a syntactic match is only a candidate. Other URL forms on `github.com` never fall back to host-wide patterns. Suppress origin matches for `gitlab.com`, `bitbucket.org`, and `codeberg.org`; the workflow must also withhold when it recognizes additional multi-tenant hosts. Document these rules in `references/webfetch-trust-scopes.md`; update tests and the report matcher when adding hosts.
- [ ] Report `summaryVersion: 2`, native inspector rules, `resources` with `action` and `resource` replacing legacy `inputs` with `permission` and `input`, and `webfetchRequestedUrlMatches: [{ scope: { kind: "origin" | "github-owner", origin, owner? }, proposedPattern, requestedUrls, distinctRequestedUrlCount }]`. Sort matches by pattern and URL lists lexically. Missing databases yield empty resources and matches and the existing actionable missing-state message. A candidate is not a recommendation until Task 08 checks role and guards. `*` saved approval never enters the requested URL set.
